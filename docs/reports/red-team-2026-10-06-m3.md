## Lens results (no findings)

- **DST sweep:** `day_moment_from_utc` pinned by ct fixtures — Paris winter (CET +1), summer (CEST +2), and the 2026-03-29 spring transition (01:30 UTC → 03:30 wall). TZ-TRUTH holds: mosque IANA zone is authoritative, `Local` only as the documented fallback.
- **Second-math invariants:** fuzz property `next_prayer_at_contract` (256 cases): selection matches the minute model, `into + remaining == interval` always, remaining bounded `1..=86400` — degenerate all-equal sets included.
- **Panic sweep:** no `unwrap`/`expect` on external data; the two `expect`s in `day_moment_from_utc` assert a chrono-internal invariant (wall time < 24 h), unreachable from input. `u8` narrowing goes through `try_from` with a `None` arm.
- **Layering:** `use mawaqit_api` still only under `src/infrastructure/` (gate-run below). `ui → application → domain` respected; event/command vocabulary lives in `ui::app`, runtime imports inward.
- **Honesty:** `Failed` screens show the error verbatim; `NoMosque` explains the path forward; nothing fakes a countdown when `last_now` is absent (gauge simply doesn't render).
- **Privacy:** no telemetry, no logging; `--mosque` override is session-only and never silently persisted.

## Bach verdict

The countdown is honest down to its inputs: every number on screen traces to `Clock → Tick → TzSource → next_prayer_at`, each step tested in isolation and as a contract. The lane shipped one piece of test-only API pretending to be production code (F1) and one untested boundary crossing (F2) — both caught here, not in production. M4 inherits a command channel with a note, not a mystery.
